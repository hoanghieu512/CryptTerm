# Implementation Plan: zk-core

## Overview

This plan builds the pre-check, the proof bundle codec, the generated circuit identity and shipped verification key, the prove service with its worker, and the verifier, test-first. Task 0 makes the two steering edits and commits the spec files. Group 1 adds the circuit boundary tests, `checkBatch`, the digest shape check and the circuit-auditor agent. Group 2 adds the bundle codec, the Identity_Script, the generated identity files, the verification key asset and the asset check script. Group 3 adds the worker protocol, the Prove_Service and the Verifier. Group 4 adds the full-proof tests and the static scan, runs everything once and hands over to huynh. The browser harness with the Playwright check (4.2) moved to the `terminal-ui` spec, and the spike removal (4.3) moved to Task 7, as MOVED, NOT DONE (see Notes). Each group ends with one commit that also stages the task-tracking files. Nothing is pushed. The order of the groups is binding.

Rules for every task:

1. Evidence before status (`structure.md`). A task is marked completed only after its "Done when" check was run in this session, and the report quotes the actual command and its output (`git log -1 --oneline` for commits, `ls` or a file listing for created files, the test summary line for tests). Never report a hash, a file, a size or an output that was not produced in this session. A failing check leaves the task unchecked. It is not a stop point: fix the cause in the files the task owns, run the check again, and quote both outputs.
2. Existing code stays unchanged. The circuit sources `main.nr`, `hash.nr`, `merkle.nr` and `posting.nr`, the Artifact `src/zk/artifacts/ledger_audit.json` and its `ledger_audit.meta.json`, and every existing file in `src/zk` and `src/ledger` are not edited, with two exceptions that add exports only: task 1.3 adds the `export` keyword to `hasExactDigestKeys`, `ROOT_HEX_PATTERN` and `SIGNATURE_HEX_PATTERN` in `src/ledger/digest.ts` and changes nothing else in it, and task 2.3 adds the exports `VK_URL` and `loadVkFromUrl` to `src/zk/artifact.ts` and changes nothing else in it. The spike files (`spike*.ts`, `spike.html` and the others listed in task 4.3) stay untouched in `zk-core` (their removal moved to Task 7). If any other existing `src/zk` or `src/ledger` file must change, STOP and ask huynh. Edits to existing files outside `src/` are named in the tasks that make them: `package.json` (2.3, 4.2, 4.3), `vite.config.ts` (4.2, 4.3), `tsconfig.json` (4.2), `tests/support/zk-env.ts` (1.2 if needed, 4.1), `tests/zk/proof-isolation.test.ts` (4.3), `circuits/ledger_audit/src/tests.nr` and `test_support.nr` (1.1), `docs/writeup-notes.md` (1.4).
3. Amounts are `bigint` cents. No `Number`, `parseInt` or `parseFloat` on money. No `console.*` and no network call in `src/ledger` or `src/zk` other than the existing same-origin loaders. Test data is synthetic only. No batch contents, postings, accounts, amounts, salts or witness values appear in a report, a log or a commit message. Reports quote counts, step names and hashes of public files only. Browser code verifies and never signs.
4. Look up before writing. Do not write circuit, prover, worker, Vite or Playwright code from memory (`tech.md`). Check the docs through Context7 or the official documentation, cross-check package names and versions against the installed `node_modules` and the npm registry, and record in the task report what was looked up and where. The lookups named in the tasks are: the Kiro CLI custom agent format and headless run flags (1.4), the Vite worker and asset URL forms (3.2), and the Playwright 1.62.0 config and the Vite 8 `build.rolldownOptions.input` and `vite preview` options (4.2).
5. Commit policy. Stage files by name, never with `git add -A` or `git add .`. Run `git status --short` before each commit. Never amend or rewrite history. NEVER push; huynh pushes. Commits happen in task 0 and in the last sub-task of each group (1.5, 2.4, 3.4, 4.4). The group-end commit also stages `.kiro/specs/zk-core/tasks.md` and, if it exists, `.kiro/specs/zk-core/tasks.meta.json`.
6. Tests first in each group. The test sub-task runs before the implementation sub-task and its failing output is quoted before the implementation exists. A test that covers code that already exists is expected to pass at once, and its passing output is quoted instead. Property tests use `runProperty` from `tests/support/pbt.ts`, carry the fixed seed and `numRuns` from the design "Testing Strategy" table, and are tagged with a comment `Feature: zk-core, Property <n>: <text>`. Every test title contains its name from the design table, so `npx vitest run <path> -t <name>` selects it. When a property finds a real bug, add a regression example test and append an entry to `tests/PBT-LOG.md`.
7. Typecheck timing. Test files import modules before those modules exist, so `npm run typecheck` fails in the middle of a group. Each Done-when says where `npm run typecheck` is first required to exit 0.
8. Long commands. Use `--run` modes (`vitest run`, never watch mode). Never start `npm run dev`. The Playwright run starts and stops its own preview server through `webServer`, so it needs no background process. Commands that can exceed two minutes (`npm run test:proof`, `npm run test:e2e`) are run with an explicit timeout of at least 600000 ms.
9. Numbering. References between tasks use the numbers of this document only.

Decisions on the items that were flagged for review. No flagged item is open.

- **Requirement 7.7: accepted.** The literal text says `npm run build` must put `ledger_audit.vk` into `dist`. The current production build emits no verification key file, because the placeholder `App` imports nothing from `src/zk`. `dist_vk_asset` therefore runs on the e2e build output (`node_modules/.cryptterm-e2e`), not on `dist`, and the Vite content hash means the file is `assets/ledger_audit-<hash>.vk`. The `terminal-ui` spec adds the run on `dist` in its first wiring task. Task 2.3 tests the check script on fixture directories only, and task 4.2 runs it on the e2e build output.
- **Confirmed by huynh: harness and Playwright edits.** Task 4.2 edits `package.json` (new scripts and the exact-pinned dev dependency `@playwright/test` 1.62.0, so `package-lock.json` changes too), `vite.config.ts` (an `e2e` mode), `tsconfig.json` (`include`), and adds the root file `playwright.config.ts`. The harness page is built into `node_modules/.cryptterm-e2e`, never into `dist`.
- **Confirmed by huynh: script name.** The browser run is `npm run test:e2e`, next to `test:circuit` and `test:proof`.
- **Confirmed by huynh: proof-isolation edit and spike list.** `tests/zk/proof/proof-smoke.test.ts` imports `SPIKE_WITNESS`, so it is removed with the spike files, and the two references to it in `tests/zk/proof-isolation.test.ts` are repointed in task 4.3. The list of spike files in task 4.3 stands.
- **Confirmed by huynh: numbering.** The task numbering of this document (task 0 and groups 1 to 4, 17 sub-tasks) stands.
- **Digest shape rules.** `src/ledger/digest.ts` gets exports only (`hasExactDigestKeys`, `ROOT_HEX_PATTERN`, `SIGNATURE_HEX_PATTERN`, design "Architecture"), and `src/ledger/digest-shape.ts` imports them and restates none of them.
